# Vangers World — аддон Blender для миров VMP

Редактор поверхностей Vangers в Blender: загрузка мира (`.vmp` + `world.ini`),
правка двух слоёв рельефа как мешей и выгрузка обратно.

Это порт инструментов SURMAP (`surmap/` в репозитории
[`KranX/Vangers`](https://github.com/KranX/Vangers)) на Python. Всё поведение
формата поверено по исходникам на C++, а не угадано.

## Установка

1. Скопируйте папку в `Blender/<версия>/scripts/addons/vangers_world` (имя папки
   должно быть `vangers_world` — оно же записано в `id` манифеста).
2. В Blender: `Edit ▸ Preferences ▸ Add-ons ▸ Install from Disk…` и выберите
   `__init__.py`, либо просто перезапустите Blender.
3. Панель появится в 3D-видовке: `N` → вкладка **Vangers**.

Разработка ведётся под **Blender 5.2 LTS**; в аддоне есть и `bl_info` (legacy),
и `blender_manifest.toml` (extensions).

## Как пользоваться

1. **Import world** — укажите `output.vmp`. Рядом должен лежать `world.ini`
   (размер мира, палитра, цвета). Появится коллекция `VangersWorld` с двумя
   мешами:

   | Объект | Что это | Размер |
   |---|---|---|
   | `Vangers_upper` | верхняя поверхность, 1 вершина на воксель | `width × depth` |
   | `Vangers_lower` | нижняя поверхность, 1 вершина на **пару** | `width/2 × depth` |

   Полный мир импортировать нельзя: у fostral 2048×16384 = **33.5 млн** вокселей.
   Импортируйте окно и двигайте `X start` / `Y start`.

2. **Лепите** как обычные меши. Верхняя поверхность — это то, что видно;
   нижняя — underside мостов. Обе сетки имеют постоянную топологию, поэтому
   работают Sculpt и штатный Undo.

3. **Материал** (`terrain` 0..7, 0 — вода, 1 — основной) — атрибут `terrain`
   на меше. «Paint material» красит его вокруг 3D-курсора. Верхний и нижний
   материал независимы.

4. **Мост** — «Add bridge» красит признак double-уровня под 3D-курсором.

5. **Export world** — пишет `.vmp` и рапортует, что изменилось.

## Что важно знать о формате

Всё это проверено на настоящих мирах из репозитория Vangers, а не взято из
документации.

- **Карта всегда 2048 вокселей в ширину** (`Map Power X = 11`), высота — из
  `Map Power Y`. Ось X — **тор** (`x & 2047`), ось Y — обычная.
- **Пара** — это чётный столбец `e` и нечётный `e+1`. Флаг `DOUBLE_LEVEL`
  стоит **на обоих** байтах пары (проверено: количества чётных и нечётных
  double-флагов совпадают точно). `height[e]` — нижняя поверхность,
  `height[e+1]` — верхняя. Чётный байт флагов хранит материал низа, нечётный —
  верха.
- **Дельта тоннеля** (по 2 бита в каждом байте пары, `d4 = (delta_even << 2) |
  delta_odd`, толщина = `(d4+1)*8`) — это **не рисунок, а физика**: её читает
  `GET_THICKNESS_ATTR` в `src/3d/dynamics.cpp` и запросы коллизий в
  `src/units/hobj.cpp`. Рендереры её не используют вообще.
- **Инвариант «мост» — соглашение инструмента, а не свойство данных.** В
  `fostral` **138 752 пары (7.2%)** уже тоньше допустимого тоннеля (разрыв
  меньше 32 вокселей, вплоть до −209): это козырьки и нависания, а не тоннели.
  Дельта в поставляемых мирах тоже **не выводится из текущей геометрии** —
  `d4` принимает значения 0..15, упирается в потолок `MAX_RDELTA` (426 тыс.
  пар с толщиной 128), и пары с одинаковым `d4` имеют разрывы от −61 до 116.

  **Отсюда решение: солвер никогда не пересчитывает пары, которые автор не
  трогал.** Пересчёт всего мира изменил бы физику десятков тысяч тоннелей.
- `LINE_render` в оригинале рисует double-пару по **нижней** поверхности
  (её высота и её материал) на обоих столбцах — в отличие от `regRender`,
  который рисует настил. Это воспроизведено дословно, потому что на этом
  стоит проверка по эталонному хешу.

## Солвер (что автор, что вывод)

| Слой | Кто задаёт |
|---|---|
| признак `double` (мост есть / нет) | **автор** |
| верхняя и нижняя высоты | **автор** |
| материалы (0..7) | **автор** |
| дельта тоннеля | **вывод** из разрыва |
| схлопывание моста | **вывод** при экспорте |

Правила солвера:

- **Новый мост** никогда не разрушается: если разрыва не хватает, нижняя
  поверхность опускается до минимально допустимого (`up - 32`).
- **Сдвинутый настил**: если дек опустился на пол, пара схлопывается, пол
  выживает (высота и материал низа). Это то же, что делает `pixSet`.
- **`enforce=True`** (галочка при экспорте) дополнительно чинит весь мир —
  полезно для миров с нуля, опасно для существующих.

Солвер — пакетная замена последовательным правкам `pixSet`: топология не
мутируется во время лепки, поэтому Undo Blender работает как обычно, а все
последствия вычисляются на экспорте.

## Архитектура

```
core/        формат и модель, НЕ импортирует bpy — тестируется отдельно
  constants.py  порт констант из src/common.h, src/terra/world.h
  ini.py        парсер world.ini
  config.py     WorldConfig: чтение и запись
  vmp.py        чтение/запись .vmp
  vpr.py        таблица уровня воды (LoadVPR)
  surface.py    высоты, флаги, доступоры double-уровня
  window.py     окна с учётом тора по X
  solver.py     инвариант тоннеля
  palette.py    PalettePrepare
  render.py     RenderPrepare + LINE_render
mesh/        мосты между numpy и Blender
  build.py      окно → два меша + атрибуты + цвета
  sync.py       меши → поверхность (экспорт)
ops/         операторы: import / export / new world / paint bridge / paint material
ui/          панели
tests/       тесты (запускаются в Blender, pytest не нужен)
```

## Тесты

```
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background \
  --factory-startup --python tests\run_tests.py
```

22 теста, ключевые критерии приёмки:

- **побайтовый round-trip** `.vmp` на всех поставляемых мирах;
- **экспорт нетронутого мира — побайтово no-op** (солвер ничего не меняет);
- **хеш `LINE_render` совпадает с эталоном** `fed77a5d` на всех 33.5 млн
  вокселей fostral — то есть порт раскраски совпадает с референсной
  реализацией бит-в-бит;
- новый мост чинится, а не рушится; нетронутые пары сохраняют дельту;
- идемпотентность солвера.

## Что ещё не сделано

- **`.vmc`** (сжатый формат) — кодек Хаффмана не портирован; работаем с
  `.vmp`. Конвертацию можно сделать в уже готовом
  [`surmap-typescript`](https://github.com/DileSoft/surmap-typescript).
- **`.vpr` для новых миров** — заголовок файла сложный (сетки, секции, части);
  запланировано патчить шаблон, а не собирать с нуля.
- **`regRender`** — точная отрисовка с тенями для сверки с игрой; в Блендере
  используется приближение без прохода теней.
